# Backend Architecture (Member 3)

## Overview

Member 3 implements the optimization and code generation backend for the MiniC compiler. The backend transforms Three-Address Code (TAC) generated by Member 2 through a pipeline of optimization passes, then generates x86 assembly output.

## Pipeline Stages

```
TAC (from Member 2)
    ↓
[Structured IR Conversion] — in-memory representation
    ↓
[Optimization Passes]
  - Constant Folding (compile-time evaluation of literal expressions)
  - Dead Code Elimination (remove unused temporaries)
  - Common Subexpression Elimination (reuse identical expressions)
    ↓
[Register Allocation]
  - Liveness Analysis (determine when temporaries are live)
  - Linear-Scan Allocation (assign temporaries to physical registers)
  - Spill Management (stack allocation for overflow)
    ↓
[Code Generation]
  - x86-64 assembly emission
  - Calling convention handling (System V ABI)
  - Function prologue/epilogue
```

## Architecture Components

### 1. Structured IR (`backend.h`, `backend.c`)

Defines the canonical TAC representation in memory:

**TAC Instruction Kinds:**
- `TAC_VAR` — variable/array declaration
- `TAC_ASSIGN` — assignment from lvalue to lvalue
- `TAC_ASSIGN_CONST` — assignment from constant
- `TAC_BINOP` — binary operation (arithmetic, logical, bitwise, comparison)
- `TAC_UNOP` — unary operation
- `TAC_ARRAY_LOAD` / `TAC_ARRAY_STORE` — array indexing operations
- `TAC_MEMBER_LOAD` / `TAC_MEMBER_STORE` — struct member access
- `TAC_PARAM` — function argument passing
- `TAC_CALL` — function call
- `TAC_LABEL` — control flow target
- `TAC_JUMP` / `TAC_COND_JUMP` — unconditional and conditional jumps
- `TAC_RETURN` — function return
- `TAC_BREAK` / `TAC_CONTINUE` — loop control (resolved during IR construction)

**Operand Kinds:**
- `OPERAND_CONST_INT`, `OPERAND_CONST_FLOAT`, `OPERAND_CONST_BOOL`, `OPERAND_CONST_CHAR` — literals
- `OPERAND_TEMP` — compiler-generated temporary (`t0`, `t1`, ...)
- `OPERAND_VAR` — source variable name
- `OPERAND_LABEL` — control flow label
- `OPERAND_STRING` — string literal reference

### 2. Optimization Passes (`optimizer.h`, `optimizer.c`)

Implements phase-weighted optimization with configurable passes:

#### Constant Folding
Evaluates expressions containing only literal operands at compile time:
- **Integer:** `+`, `-`, `*`, `/`, `%`, `&`, `|`, `^`, `<<`, `>>`, comparisons, logical ops
- **Float:** `+`, `-`, `*`, `/`
- Converts folded expressions to `TAC_ASSIGN_CONST`

Example: `10 + 5` → `t0 = 15`

#### Dead Code Elimination
Removes assignments to temporaries that are never read:
- Analyzes liveness of all temporaries
- Marks unused definitions as no-ops
- Prevents accumulation of dead stores

Example: `t0 = 99` (if `t0` never used) → removed

#### Common Subexpression Elimination (CSE)
Detects and reuses identical expressions within a function:
- Per-function analysis (scoped to avoid inter-procedural aliasing issues)
- Matches on operator and operand names/values
- Replaces duplicate with assignment from first computation

Example:
```
t0 = a + b
...
t1 = a + b  → t1 = t0 (reuse)
```

### 3. Register Allocation (`regalloc.h`, `regalloc.c`)

Implements linear-scan register allocation with spill handling:

**Physical Registers:**
- Caller-clobbered (available): `eax`, `ecx`, `edx`
- Callee-saved (must preserve): `ebx`, `esi`, `edi`

**Liveness Analysis:**
- Forward pass to determine first/last use of each temporary
- Computes live ranges for all temporaries in a function

**Linear-Scan Allocation:**
- Processes instructions sequentially
- Allocates free registers to temporaries
- When registers exhausted, spills temp with latest last-use
- Assigns spill slots on stack (negative offset from base pointer)

**Calling Convention:**
- System V AMD64 ABI (Linux)
- Integer args: `rdi`, `rsi`, `rdx`, `rcx`, `r8`, `r9`
- Return value: `rax` / `rdx:rax` (simplified here to just `rax`)
- Caller saves: responsibility of caller
- Callee saves: `rbx`, `r12`, `r13`, `r14`, `r15`, `rbp`, `rsp`

### 4. Code Generation (`codegen.h`, `codegen.c`)

Lowers optimized TAC to x86-64 assembly:

**Instruction Selection:**

| TAC Op | x86 Assembly |
|--------|-------------|
| `a = b` | `mov src, dst` |
| `a = b + c` | `mov b, eax; add c, eax; mov eax, a` |
| `a = b - c` | `mov b, eax; sub c, eax; mov eax, a` |
| `a = b * c` | `mov b, eax; imul c, eax; mov eax, a` |
| `a = b / c` | `mov b, eax; cqo; idiv c; mov eax, a` |
| `if b goto L` | `cmp 0, b; jne L` |
| `goto L` | `jmp L` |
| `L:` | `L:` (label) |
| `call f` | `call f` |
| `return a` | `mov a, eax; jmp .L_return` |

**Function Layout:**
```asm
.globl func_name
.type func_name, @function
func_name:
    push %rbp
    mov %rsp, %rbp
    sub $128, %rsp           # Allocate local stack space
    # ... function body ...
.L_return:
    leave
    ret
```

## Current Limitations

1. **Pointer Semantics:** Limited support since MiniC doesn't fully model pointer types. Address/dereference operators treated minimally.

2. **Floating Point:** Float arithmetic generated but not yet validated on actual x86 (current codegen uses integer registers throughout).

3. **String Literals:** Emitted as references but not yet placed in `.rodata` section.

4. **Optimization Scope:**
   - CSE limited to single function (no inter-procedural analysis)
   - No dead function elimination
   - No loop optimizations (hoisting, invariant elimination)
   - No inlining

5. **Code Generation:**
   - Simplified calling convention (assumes all args fit in registers)
   - No stack alignment enforcement
   - No SIMD or vectorization
   - x86-64 only (no x86-32, MIPS, or other targets yet)

## Usage

After compilation, the structured TAC program is available as `ir_tac_program` (global).

To use the backend:

```c
/* After semantic analysis and TAC generation */
if (ir_tac_program) {
    /* Run optimizations */
    tac_optimize(ir_tac_program);
    
    /* Generate x86 assembly */
    tac_codegen_x86(ir_tac_program, stdout);
}
```

## Future Work

1. **Full TAC Structuring:** Convert all IR generation to build structured TAC (currently partial).
2. **x86-32 Backend:** Support 32-bit x86 systems.
3. **MIPS Backend:** Extend to MIPS-I ISA.
4. **Advanced Optimizations:** Peephole optimizations, loop transformations, partial redundancy elimination.
5. **Debug Info:** Emit DWARF debug symbols for stepping/profiling.
6. **Static Analysis:** Pointer escape analysis, must-alias detection, interval analysis.
